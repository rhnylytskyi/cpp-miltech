# Домашнє завдання 18: Периферійний пристрій на базі ESP32-S3 (UART & I2C)

Цей проєкт реалізує embedded-систему асинхронного збору телеметрії та обробки команд для мікроконтролера **ESP32-S3** за допомогою офіційного фреймворку **ESP-IDF**.

## 📌 Технічна архітектура проєкту

Програма координує паралельну роботу двох цифрових інтерфейсів без взаємного блокування:
1. **Інтерфейс I2C (Шина даних)**: Використовує апаратні піни `GPIO_8` (SDA) та `GPIO_9` (SCL) для швидкого зчитування сирих блоків даних з регістрів акселерометра MPU-6050.
2. **Інтерфейс UART (Консоль керування)**: Працює на швидкості `115200` бод, забезпечуючи безперервну трансляцію телеметрії та асинхронний розбір текстових команд користувача.

### 🛡️ Інженерна дисципліна та захист системи
* **Захист від Stack Overflow**: Для задачі приймання команд UART (`uart_cmd`) виділено збільшений стек розміром `4096` байт. Це повністю нівелює ризик переповнення пам'яті під час виконання важких системних функцій виводу `printf`.
* **Асинхронний таймер**: Робота періодичного опитування датчика побудована на базі апаратного високоточного `esp_timer`. Обробник переривання (`timer_callback`) відповідає суворим стандартам розробки: він максимально короткий і лише перемикає атомарний (`volatile`) прапорець готовності.
* **Захист сторожового таймера (Watchdog)**: У головному циклі програми встановлено обов'язковий квант часу `vTaskDelay(20 ms)`. Це дає ядру операційної системи FreeRTOS можливість "дихати", годувати сторожовий таймер та уникати аварійних перезавантажень процесора в умовах віртуалізації.

## 🕹️ Доступні команди (UART)

Введення команд здійснюється наосліп безпосередньо у вікно терміналу симуляції:

* `p <значення у мс>` — Динамічно змінює частоту апаратного таймера (дозволений діапазон: від 50 до 5000 мс). Автоматично перемикає режими виводу: `fast` (≤ 200мс), `slow` (≥ 800ms) або `normal`.
* `reset` — Повертає налаштування періоду опитування до стандартних заводських параметрів (500 мс, режим `normal`).
